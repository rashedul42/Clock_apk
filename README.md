# Clock App — Flutter (Provider)

A 4-tab clock app (Alarm · World Clock · Timer · Stopwatch) with hand-painted
`CustomPainter` visuals on top of each screen, and a **Task-Based Alarm
Dismissal System** that forces the user to complete a real task before an
alarm can be silenced.

## Architecture

```
pubspec.yaml

lib/
  main.dart                    # MultiProvider root + ring-state router
  theme/app_theme.dart         # Colors, fonts, component themes
  models/
    alarm.dart                 # Alarm entity (time, repeat, sound, snooze, taskConfig...)
    alarm_task.dart            # AlarmTaskType enum + AlarmTaskConfig (per-task settings)
    timer_preset.dart
    world_city.dart
  providers/                   # State management (Provider / ChangeNotifier)
    alarm_provider.dart         # Alarm CRUD + the ringing/dismiss state machine
    timer_provider.dart
    stopwatch_provider.dart
    world_clock_provider.dart
  widgets/painters/             # CustomPainter top-half visuals
    seven_segment_painter.dart  # Retro LCD 7-segment digits (Stopwatch)
    hourglass_painter.dart      # Animated sand-drop hourglass (Timer)
    twin_bell_painter.dart      # Classic red alarm clock, live hands (Alarm)
    big_ben_painter.dart        # Big Ben tower, live hands (World Clock)
  screens/
    home/main_nav_screen.dart   # Bottom nav shell, 4 tabs
    alarm/
      alarm_list_screen.dart
      add_alarm_screen.dart     # Time wheel + settings + Dismissal Task picker

      dismissal_tasks/
        task_base.dart          # Shared TaskCompletedCallback contract + chrome
        math_task.dart          # 1. Math Challenges
        exercise_task.dart      # 2. Fitness (push-ups/squats, accelerometer or camera)
        photo_task.dart         # 3. Image Recognition (photograph a target object)
        qr_scan_task.dart       # 4. QR / Barcode Scan

    timer/timer_screen.dart
    stopwatch/stopwatch_screen.dart
    world_clock/world_clock_screen.dart
```

## Task-Based Alarm Dismissal System

**Data model** (`models/alarm_task.dart`):
- `AlarmTaskType` — `math | fitness | imageRecognition | qrScan | speechReading` (or `null` on `AlarmTaskConfig.taskType` for no task).
- `AlarmTaskConfig` — holds the settings for *whichever* type is chosen (problem count/difficulty, exercise/reps/detection mode, target object label, QR payload, reading phrase). Every `Alarm` carries one `AlarmTaskConfig`.

**Flow**:
1. `AlarmProvider` polls the clock every second; when an enabled alarm matches, `ringingAlarm` is set (non-null) and `notifyListeners()` fires.
2. `main.dart`'s `_RootRouter` watches `ringingAlarm` and swaps the *entire app* for `AlarmRingScreen` — the normal UI (including any back navigation) isn't in the tree while an alarm rings.
3. `AlarmRingScreen` reads the ringing alarm's `taskConfig.taskType` and mounts the matching task widget from `dismissal_tasks/`.
4. Each task widget takes a single `onCompleted` callback. It is **only** invoked once the user has genuinely satisfied the task (all math problems correct, all reps counted, correct QR payload scanned, phrase recognized above a similarity threshold, etc.) — wrong attempts loop the task, they never call it.
5. `onCompleted` is wired to the *one* call to `AlarmProvider.dismiss()` in the whole screen. `PopScope(canPop: false)` blocks the back gesture, so there is no other way off this screen.

### Per-task integration points (stubbed for you to wire real ML/services)
- **Fitness / camera mode**: swap `_CameraRepCounterStub` in `exercise_task.dart` for a pose-estimation package (e.g. `google_ml_kit` pose detection).
- **Image Recognition**: swap `_classifyImage` in `photo_task.dart` for a real on-device classifier (e.g. `google_ml_kit` Image Labeling or a TFLite model), comparing labels against `targetObjectLabel`.
- **QR/Barcode**: `qr_scan_task.dart` already uses `mobile_scanner` live; `qrPayload` is set once by the user (manual entry field is provided in `add_alarm_screen.dart`; swap for a real one-shot scan-to-register flow).
- **Speech Reading**: `reading_task.dart` uses `speech_to_text` for a live transcript, fuzzy-matched (≥80% word overlap) against the target phrase.

## Setup
```bash
flutter pub get
flutter run
```
This project ships with hand-written `android/`, `ios/`, and `web/` platform
folders (not generated by `flutter create`, since that requires the Flutter
SDK/network access this assistant's sandbox doesn't have). They follow the
standard Flutter project layout so IDEs/build services (Android Studio,
Xcode, FlutLab, VS Code) recognize the project structure immediately.

**Before your first real build**, a few placeholders need real values:
- `android/app/build.gradle` / `ios/Runner/Info.plist`: bundle id is set to
  `com.example.clock_app` / `com.example.clockApp` — change to your own.
- `assets/sounds/`: currently just a README — drop in real `.mp3` files
  named to match the sound picker in `add_alarm_screen.dart` (e.g.
  `default_chime.mp3`, `gentle_wake.mp3`, `classic_bell.mp3`,
  `digital_beep.mp3`, `nature_birds.mp3`). `AlarmRingScreen` already loops
  whichever one the alarm is set to via `audioplayers`, and vibrates via
  the `vibration` package when the alarm's "Vibrate" toggle is on.
- App icons (`android/.../mipmap-*/ic_launcher.png`,
  `ios/Runner/Assets.xcassets/AppIcon.appiconset/*.png`,
  `web/icons/*.png`, `web/favicon.png`) are simple placeholder glyphs
  generated for this project — swap for real branded icons whenever you
  like.
- `ios/Runner.xcodeproj/project.pbxproj` and
  `ios/Runner/GeneratedPluginRegistrant.*` are hand-assembled to match
  Flutter's standard template; running `flutter pub get` (which runs
  CocoaPods install) regenerates the plugin registrant correctly for the
  plugins in `pubspec.yaml`. If Xcode ever complains about the project
  file itself, `flutter create .` from the repo root will safely
  regenerate just the native scaffolding without touching `lib/`.
- **Not yet wired**: `flutter_local_notifications` + exact-alarm scheduling
  for reliably firing alarms while the app is fully backgrounded/killed —
  `AlarmProvider` currently polls the clock only while the app process is
  alive. This is the natural next integration point for production use.

Merge any additional Android permissions your target SDK requires into
`android/app/src/main/AndroidManifest.xml` (camera, mic, vibrate, exact
alarms, and notifications are already declared there for the five
dismissal tasks).

On the **Alarm** tab, tap the ▶︎ icon next to any alarm to trigger it
immediately (`AlarmProvider.debugTriggerRing`) and exercise the dismissal
flow without waiting for the real time to hit.

## Building an APK without a local Flutter install

`.github/workflows/build.yml` builds a debug APK on every push to `main`
(and on demand via the Actions tab's "Run workflow" button) — useful since
sandboxed environments (including this one) can't compile real native
code or access device sensors.

1. Push this project to a GitHub repo.
2. Go to the **Actions** tab → **Build Android APK** → **Run workflow** (or just push a commit).
3. When the run finishes (green check), open it and download the
   **clock-app-debug-apk** artifact from the bottom of the run summary —
   it's a zip containing `app-debug.apk`.
4. Copy that APK to your phone and install it (enable "install unknown
   apps" for whichever app you transfer it with).

This is a **debug** build, so it's unsigned and larger than a release
build, but it installs and runs identically for testing — including the
real accelerometer, camera, QR scanner, and speech-to-text used by the
dismissal tasks, none of which work in a sandbox/emulator without care.
Swap the workflow's last build step for `flutter build apk --release`
(with your own signing config in `android/app/build.gradle`) once you're
ready to distribute a signed build.
